# ChunkFlow experiment harness (`/workspace/sglang/offload_profiling/`)

## 1. How the paper's experiments are launched

Everything goes through the `sglang generate` CLI (console script `sglang = "sglang.cli.main:main"`, `python/pyproject.toml:157` -> `python/sglang/cli/generate.py` -> `sglang.multimodal_gen.runtime.entrypoints.cli.generate.generate_cmd`), wrapped in Nsight Systems. The canonical paper command (from `offload_profiling/run_access.sh:159-168`) is:

```bash
nsys profile --trace=cuda,nvtx,osrt --cuda-memory-usage=true \
  --trace-fork-before-exec=true --kill=none --force-overwrite=true \
  --output="$NSYS_OUTPUT_PREFIX" \
  sglang generate \
    --model-path "$MODEL_PATH" --text-encoder-cpu-offload --pin-cpu-memory \
    --dit-layerwise-offload true --dit-offload-prefetch-size 1 \
    --num-gpus "$NUM_GPUS" --ulysses-degree "$ULYSSES_DEGREE" \
    --attention-backend "$ATTENTION_BACKEND" \
    --prompt "$PROMPT" --num-outputs-per-prompt "$NUM_OUTPUTS_PER_PROMPT" \
    --num-frames "$NUM_FRAMES" --height "$HEIGHT" --width "$WIDTH" \
    --num-inference-steps "$NUM_INFERENCE_STEPS" \
    --guidance-scale "$GUIDANCE_SCALE" [--guidance-scale-2 "$GUIDANCE_SCALE_2"] \
    [--enable-torch-compile] \
    --perf-dump-path "$PERF_OUT" \
    --output-path "$OUTPUT_DIR" --output-file-name "$OUTPUT_FILE_NAME" [--no-save-output]
```

Two generations of scripts:

**Standalone Wan-only mock-comm trio (older, 1 GPU + emulated comm):** `run.sh`, `run_no.sh`, `run_old.sh`. - `run.sh`: ChunkFlow ("new"): `--dit-layerwise-offload true`, `SGLANG_DIT_COMM_AWARE_OFFLOAD=1`, `SGLANG_DIT_PHASE_AWARE_PREFETCH=1`, chunk 16 MB (lines 86-99).
- `run_no.sh`: no offload: `--dit-layerwise-offload false`, `SGLANG_DIT_COMM_AWARE_OFFLOAD=0` (lines 62, 87).
- `run_old.sh`: baseline layerwise offload ("old"): `--dit-layerwise-offload true` but `SGLANG_DIT_COMM_AWARE_OFFLOAD=0` (lines 62-63, 87) - i.e. the original non-chunked prefetcher (`layerwise_offload_original.py`).

**Cluster/real-SP scripts (used for the paper's 2xH100 numbers):** `run_access.sh`, `run_access_no.sh`, `run_access_old.sh`, `run_access_phase.sh` - multi-model (`$1` = model name), NUM_GPUS=2/ULYSSES=2 defaults, mock comm **off** (`SGLANG_WAN_MOCK_COMM_ENABLE:-0`), `--no-save-output` by default (`PROFILE_SAVE_OUTPUT_ARTIFACTS=0`), torch-compile on unless `DISABLE_TORCH_COMPILE=1`/`ENABLE_TORCH_COMPILE=0`. They contain HPC `module purge; module load Miniforge3/... CUDA/12.8.0 GCC/12.3.0` lines (e.g. `run_access.sh:9-12`) that only work on the Lmod cluster.
- `run_access.sh`: "new" comm-aware run (`SGLANG_DIT_COMM_AWARE_OFFLOAD=1`, `SGLANG_DIT_PHASE_AWARE_PREFETCH=0`, `SGLANG_DIT_COMM_ACTIVE_WINDOW_MODE=kernel`, chunk 16 MB, lines 108-121); with `PROFILE_MODE=ratio` it becomes the partial-residency run (`SGLANG_DIT_OFFLOAD_RESIDENT_RATIO=0.4`, lines 124-126).

- `run_profile.sh` / `run_profile_dmon.sh`: orchestrators (above).
- `analyze_traces.sh` + `trace_analysis/{cpu_trace_overlap,analyze_copy_events,analyze_pcie_bandwidth,analyze_pcie_from_copies}.py`: separate CPU-side analysis of torch-profiler `*.trace.json.gz` traces under `results/traces/`.
- `nsys_query.py` / `summarize_nsys_csv.py`: ad-hoc SQL queries over nsys sqlite exports (mock vs real NCCL comm critical path) and a compact md report; not on the main `run_profile.sh` path.

## 3. Step time and peak memory measurement

- **Step time (primary)**: NVTX range `SGL_DENOISING_STEP_{i}` emitted per denoising step in `python/sglang/multimodal_gen/runtime/pipelines_core/stages/denoising.py:1031`. `analyze_nsys.sh` -> `summarize_profile_matrix.py` exports each `.nsys-rep` to sqlite (`nsys export --type=sqlite`, lines 215-249), reads `NVTX_EVENTS` matching `SGL_DENOISING_STEP_*` (lines 252-275), drops step 0, detects a "switch-step" outlier (>= 1.15x median, `detect_switch_step` lines 278-289 - catches the Wan2.2 high/low-noise model switch) and reports mean steady step time excluding it (`step_time_s`) plus raw mean (`step_time_raw_s`). Manual overrides: `NO_STEP_TIME_S`/`OLD_STEP_TIME_S`/`NEW_STEP_TIME_S`/`RATIO_STEP_TIME_S` (legacy `PHASE_STEP_TIME_S`).
- **Peak memory**: from the perf JSON written by `--perf-dump-path` (`perf_new_offload_profiled.json` etc.). `PerfLogger` dumps `memory_checkpoints` (`python/sglang/multimodal_gen/runtime/utils/perf_logger.py:378-395`) recorded in `gpu_worker.py` as `before_forward` (:279), `after_forward` (:302), `mem_analysis` (:159-162), each with `peak_allocated_mb`/`peak_reserved_mb` from torch CUDA allocator stats. `summarize_profile_matrix.py:extract_peak_memory_pair` (lines 175-193) prefers `mem_analysis` > `after_forward` > `before_forward`; env overrides `{NO,OLD,NEW,RATIO}_PEAK_RESERVED_MB` / `..._PEAK_ALLOCATED_MB`. `total_duration_ms` comes from the same JSON.
- **Accurate host timing**: `SGLANG_DIFFUSION_SYNC_STAGE_PROFILING=1` inserts `torch.cuda.synchronize()` around each denoising step timer (`perf_logger.py:253-300`); `SGLANG_DIFFUSION_STAGE_LOGGING=1` enables stage timing collection even without a dump path; `SGLANG_DIFFUSION_CUDA_EVENT_STEP_PROFILING` (default 1) is the fallback CUDA-event timing.
- **Comm/prefetch metrics**: `analyze_nsys_step_metrics.py` computes per-run averages within steady step windows: `step_avg_ms`, NCCL kernel time (`%ncclDevKernel_SendRecv%`), NCCL-H2D overlap, "uncovered" H2D (prefetch memcpy time not covered by any compute kernel), and `SGL_PREFETCH_WAIT_COMM_BG` NVTX time; prefetch streams identified via NVTX markers `SGL_PREFETCH_H2D{,_BG,_SYNC,_CHUNK}` (lines 15-23, 254-307, 330-460).
- **Final artifacts**: `results/profiles/<model>/analysis/analysis_summary.md` (matrix + step metrics), `analysis_summary_matrix.md`, `analysis_summary_step_metrics.md`, `profile_matrix.csv` (`analyze_nsys.sh:159-175`). `ANALYZE_RUNS_CSV=no,old,new,ratio` selects a subset.

## 4. Mode-controlling env vars (as consumed by the code)

Read in `python/sglang/multimodal_gen/runtime/utils/layerwise_offload_chunkwise.py:2010-2110` and `layerwise_offload.py:14`:
- `SGLANG_DIT_COMM_AWARE_OFFLOAD` - master switch; ALSO selects the implementation module at import time (`layerwise_offload.py:14`: chunkwise vs original). There is **no CLI flag** for it - env only.
- `SGLANG_DIT_PHASE_AWARE_PREFETCH` - phase-aware prefetch (only meaningful with comm-aware; run_access uses 0, run.sh uses 1).
- `SGLANG_DIT_COMM_PREFETCH_CHUNK_SIZE_MB` - chunk size C (code default 32; all scripts set 16 = paper default).
- `SGLANG_DIT_OFFLOAD_RESIDENT_RATIO` - partial residency fraction in [0,1] (0 -> disabled); scripts use 0.4 for the "ratio" run. CLI twin `--dit-offload-resident-ratio` (`server_args.py:302,814`).
- `SGLANG_DIT_COMM_ACTIVE_WINDOW_MODE` = `kernel`|`launch` (how long H2D stays paused around a collective; CLI `--dit-comm-active-window-mode`, `server_args.py:303,830`).
- `SGLANG_DIT_COMM_AWARE_PATCH_TORCH_DIST`, `SGLANG_DIT_OFFLOAD_PHASE_PREFETCH_DEPTH`, `SGLANG_DIT_OFFLOAD_RESIDENT_PHASES` - secondary knobs.
- Offload on/off itself is the CLI flag `--dit-layerwise-offload true|false` plus `--dit-offload-prefetch-size 1` (`server_args.py:298-299`).
- Mock comm (Wan only, `wanvideo.py:896-946`): `SGLANG_WAN_MOCK_COMM_ENABLE`, `_EVERY_N_BLOCKS`, `_DEBUG`, `_PCIE_MB`, `_VIRTUAL_SP_DEGREE` (clamped >= 2), `_TRAFFIC_SCALE`, `_MAX_MB`.

- `SGLANG_FORCE_DIFFUSERS_TIMESTEP_EMBEDDING` (flux image models; `runtime/layers/visual_embedding.py:39`).

## 3. Architecture (how ChunkFlow is wired)
- `utils/layerwise_offload.py` is now a **runtime dispatcher**: env `SGLANG_DIT_COMM_AWARE_OFFLOAD=1` selects `layerwise_offload_chunkwise.py` (2,270 lines, "new"); otherwise `layerwise_offload_original.py` (859 lines, preserved as the "old" baseline).
- Chunkwise manager: CPU-pinned per-layer buckets split into chunks (`SGLANG_DIT_COMM_PREFETCH_CHUNK_SIZE_MB`, **16 in scripts**; the server-arg fallback default in code is 32); background `_prefetch_worker_loop()` checks `_wait_for_comm_inactive()` before each chunk; collectives call `quiesce_prefetch_for_comm()` → `quiesce_copy_stream_for_comm()` (current stream waits on copy stream). Per-step CUDA-event stats (copy bytes, wait-comm time, exposed waits) are exported through `gpu_worker._collect_offload_profile_metrics()` into the perf JSON `extra.offload_profile`.
- `comm_aware_prefetch.py`: `CommunicationActivityTracker` with two window modes — **"launch"** (active only during the host-side collective wrapper; the original paper-era behavior) and **"kernel"** (default at HEAD; `begin_kernel_region()` + NCCL-work wait loop + kernel event loop keep H2D paused until the collective's stream-level completion). Optional `patch_torch_distributed()` monkeypatch.
- Comm entry points: `layers/usp.py` (USP all-to-all — Wan, Flux; NVTX `SGL_REAL_COMM_USP_DEV{n}`, device-index parameterized, not hard-coded to 2 ranks) and `layers/attention/layer.py` (`UlyssesAttention` — HunyuanVideo).
- Models: `wanvideo.py` (+359 lines: `BLOCK_PHASE_SPECS` = entry / self_attn_tail / cross_attn / ffn, plus a **mock-comm subsystem** `SGLANG_WAN_MOCK_COMM_*` that injects synthetic PCIe D2H round-trips to emulate a *virtual SP degree* — directly relevant for emulating comm pressure), `flux.py`, `flux_2.py`, `hunyuanvideo.py` similarly instrumented.
- `stages/denoising.py`: NVTX `SGL_DENOISING_LOOP` / `SGL_DENOISING_STEP_{i}` ranges + per-step offload-profile index (analysis uses steady-state steps 1–9).
- New server args: `--dit-offload-resident-phases`, `--dit-offload-resident-ratio`, `--dit-offload-phase-prefetch-depth` (default 4 = Wan phase count), `--dit-comm-active-window-mode` (default "kernel"). Env vars override all of them.
